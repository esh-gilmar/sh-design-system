# Contribuir

1. Abra Issue descrevendo problema real, captura sanitizada e comportamento desejado.
2. Faça branch por assunto e um PR pequeno e verificável.
3. Mudanças em cores oficiais exigem confirmação com Brandbook/autorização do responsável pela identidade visual.
4. Mudanças nos tokens semânticos precisam de contexto e evidência de contraste.
5. Não publicar fonte Dax licenciada nem capturas de sistemas com dados reais no repositório público.
6. Execute npm test e npm run tokens:check.
7. Documente impacto em aplicações consumidoras antes de alterar contratos.
8. Indique explicitamente se a decisão é proposta, aprovada ou depreciada.

Não empurre arquivos direto para a main após a inicialização; use revisão de PR.
